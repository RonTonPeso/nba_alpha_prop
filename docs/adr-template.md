# ADR Template

Skeleton used while drafting the records in `docs/adr.md`. Each section has a short prompt. Keep the prose terse. The reader is a future engineer trying to understand a decision.

## Context

Two or three short paragraphs. Establish:

- What problem this ADR addresses (one sentence).
- The constraint that forces a non-trivial design (one sentence).
- Any prior state worth noting (existing tables, prior attempts, earlier milestones).

## Decision

Bulleted list. Each bullet is one design choice. Keep the bullets terse; the reasoning lives in the next two sections.

- One sentence per decision.
- Use the present tense ("Fact tables carry...").
- State the choice here. Put the reason in Consequences or Alternatives.

## Consequences

### Positive

- What this design enables. Three to six bullets.

### Negative

- What this design costs. Three to six bullets. Be honest about the costs.

## Alternatives Considered

For each rejected alternative, write a short paragraph: what the alternative was, and why it was rejected. A reader skimming the ADR should learn what was ruled out and why.

## Open Questions

Things not decided yet, or intended for a later revisit. Write them down so later work knows what is still load-bearing.
